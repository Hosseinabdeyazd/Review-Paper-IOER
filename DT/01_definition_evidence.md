## Operational extraction dimensions (no predetermined verdict)

Record each sampled definition or system as: (a) target entity / boundary; (b) digital entity and persistent state; (c) synchronization direction/trigger/rate; (d) representation of past/current/future; (e) services and model composition; (f) stakeholder, decisions, action/feedback; (g) governance and provenance; (h) spatial scale; (i) implementation and validation status. Include the **exact supporting passage and page** in the research coding database when accessible.

## Critical comparison to preserve

- Abdelrahman (2025) finds **HPRT** and **LTDS** component-pattern families (§4.1); it does **not** establish that real-time AI/ML and autonomous feedback are universal minimum requirements for building/city twins. Distinguish component occurrence from normative necessity.
- A **working** definition for our circular-domain context is in [02_working_definition.md](02_working_definition.md). It must be tested against contradictory cases, not used to screen in only studies that agree with it.
- Avoid using undefined labels such as "digital twin" as a proxy for actual system capabilities. Extract implementation evidence for each capability separately.
