# Lessons and Actions

[بازگشت به فهرست](README.md) · [یادداشت JCP-03](articles/03_Baustert_Benetto_2017.md) · [ساختار پیشنهادی](PROPOSED_MANUSCRIPT_STRUCTURE.md)

**تاریخ ایجاد:** 2026-10-01.

این دفتر فاصله میان «نکته‌ای که از مطالعه یاد گرفته‌ایم» و «تغییری که واقعاً در پروژه اعمال شده» را نگه می‌دارد. همه اقدام‌های اولیه زیر **پیشنهاد** هستند؛ نه تصمیم قطعی و نه تغییر انجام‌شده در مقاله اصلی.

## قواعد وضعیت

| وضعیت | معنی |
|---|---|
| Proposed | پیشنهاد ثبت شده؛ بررسی و تصمیم لازم است |
| Accepted | برای اجرا پذیرفته شده؛ اجرا هنوز اثبات نشده است |
| Implemented | فایل هدف واقعاً تغییر کرده؛ مسیر و commit ثبت شده‌اند |
| Verified | تغییر اجراشده با معیار پذیرش کنترل شده است |
| Deferred | فعلاً کنار گذاشته شده؛ دلیل و شرط بازگشت ثبت می‌شود |
| Rejected | پذیرفته نشده؛ دلیل نگه داشته می‌شود |

پذیرش یک پیشنهاد از سکوت یا صرف درخواست ذخیره یادداشت‌ها استنباط نمی‌شود. مسیرهای هدف زیر مفهومی یا برنامه‌ریزی‌شده‌اند و وجود فعلی همه آن فایل‌ها را ادعا نمی‌کنند.

## آزمایش پیشنهادی کدگذاری چندمحوری — A02 تا A05

**این جدول جایگزین مصوب codebook نیست.** نام فیلدها و گزینه‌ها موقت‌اند و باید با متن چند مطالعه واقعی آزموده شوند.

| فیلد آزمایشی | چه چیزی ثبت می‌شود؟ | احتیاط |
|---|---|---|
| `uncertainty_source_id` | منبع مشخص عدم‌قطعیت در یک مطالعه و یک اتصال | کل مطالعه را مجبور به یک وضعیت واحد نکنیم |
| `source_type_original` | اصطلاح و تعریف خود نویسندگان | اصطلاحات متفاوت را بی‌توضیح یکسان نکنیم |
| `source_type_harmonized` | طبقه‌بندی پیشنهادی برای مقایسه مطالعات | قاعده نگاشت و موارد نامطمئن ثبت شود |
| `reporting_status` | اطلاعات کافی، جزئی یا ناکافی | گزارش‌نشدن با انجام‌نشدن یکی نیست |
| `transfer_status` | حفظ، انتقال جزئی، کنارگذاشتن صریح، نامشخص یا نامرتبط | حذف/پنهان‌شدن نیازمند شاهد است |
| `representation_change` | بدون تغییر، تغییر نمایش یا نامشخص | تبدیل نمایش می‌تواند همراه حفظ اطلاعات رخ دهد |
| `magnitude_change` | کاهش، افزایش، بدون تغییر قابل‌تشخیص، نامقایسه‌پذیر یا ارزیابی‌نشده | مقدار هدف، واحد، معیار و مبنای مقایسه باید معلوم باشد |
| `change_basis` | داده جدید، کالیبراسیون، قید معتبر، تغییر ساختار یا حذف فرض/منبع | هر مبنا باید از منبع استخراج شود؛ صرف نام روش کافی نیست |
| `dependence_handling` | نحوه برخورد با همبستگی و وابستگی، در صورت گزارش | اطلاعات ناموجود را حدس نزنیم |
| `decision_consequence` | آیا تأثیر بر نتیجه تصمیم واقعاً ارزیابی شده است؟ | تغییر بازه نتیجه را خودکار تغییر انتخاب ننامیم |
| `evidence_locator` | DOI، بخش، صفحه و در صورت نیاز جدول/شکل | برای هر قضاوت قابل بازیابی باشد |

در صورت تأیید این طرح، یک جدول نگاشت به شش برچسب فعلی README لازم است. هیچ برچسب قبلی نباید بدون نسخه‌بندی، دلیل و کنترل اثر تغییر حذف شود.

## پرسش‌های باز برای مرور مقاله‌های بعدی

آیا مقاله‌های GIS–LCA تعریف دقیق‌تری برای گذار مقیاس و حفظ اطلاعات دارند؟ آیا مرورهای اقتصاد چرخشی معیارهای قابل‌استخراجی برای ارتباط عدم‌قطعیت با انتخاب reuse/recycle ارائه می‌کنند؟ کدام روش‌ها در منابع مختلف با شواهد مشابه پشتیبانی می‌شوند و کجا نتایج ناسازگارند؟

پاسخ‌ها فقط پس از مطالعه منابع مربوط ثبت می‌شوند؛ این پرسش‌ها یافته کنونی نیستند.
